## 提案正文

### 一、对任务的理解

本讨论要确定「两分钟辅助监测」（每两分钟扫描一次工作区）的默认启用策略，候选方案为：默认启用 / 默认关闭 / 显式询问后启用。期望结果是收敛出一个可执行方案，写入多 Agent 协作规范。

我的理解是：这不是纯技术选型，而是「自动化行为是否需要用户授权」的决策问题。监测行为会持续扫描工作区、占用上下文与资源、触发权限相关活动，因此它首先涉及用户（Rainier）的决策主权与隐私边界，其次才是功能收益。我在此独立提案阶段持以下倾向：**初始化时显式询问 Rainier 后再启用，不设默认值，避免未经同意启动**。

### 二、提案内容

**核心方案：两分钟辅助监测默认不启动，在会话初始化阶段由 claude-c 显式询问 Rainier，获得明确同意后方启用。**

具体设计如下：

1. **默认状态 = 不启用（默认不启动）**。每个新会话开始时，辅助监测定时器处于关闭状态，不自动扫描工作区。
2. **询问时机 = 会话初始化阶段**。在会话启动清单中显式向 Rainier 确认：「本会话是否启用两分钟辅助监测？」给出清晰选项（启用 / 不启用 / 自定义间隔），由 Rainier 拍板。
3. **询问前置，启用后置**。Rainier 明确选择「启用」后，才建立定时扫描机制；在此之前不产生任何定时扫描动作。
4. **主机制不受影响**。无论辅助监测是否启用，「每次向用户回复前先检查讨论文件夹」这一主机制始终生效，作为兜底；两分钟定时扫描仅是主机制之上的辅助增强，缺省关闭不破坏协作基础流程。
5. **结果会话级记录，跨会话重新确认**。Rainier 的选择记录在当前会话状态中；新会话重新询问（除非 Rainier 提供持久化授权，见待确认问题）。这符合协作规范「定时扫描依赖会话级机制（如 cron），会话退出后失效」的既有定位。
6. **询问成本最小化**。初始化仅询问一次，不打断后续讨论；若 Rainier 已启用，则后续行为与「默认启用」方案完全一致，区别只在「谁先做决定」。

### 三、主要依据

1. **用户决策主权优先**。多 Agent 协作规范明确「决策者（人）决定何时收敛结论、由人最终拍板」。自动化的每两分钟扫描涉及工作区内容读取与持续活动，属于应获用户明确同意的行为，不应以默认值悄悄启动。
2. **规范已将定时扫描定位为「辅助」**。规则原文将「每次回复前必查」定为主机制、定时扫描定为辅助，并指出其依赖会话级机制、约 7 天自动过期。辅助性功能降级为「需显式确认才启用」是自然推论，不改变规范主结构。
3. **避免未经同意的资源与隐私副作用**。每两分钟扫描会产生持续的进程活动、上下文占用与潜在权限触发。在用户不知情时启用，可能造成资源浪费、弹窗干扰、上下文提前消耗，而这些副作用用户并未同意承担。
4. **符合「决策纪律」不静默固化原则**。规范要求任何事项必须经用户明确确认才固化为结论。若定时器默认开启，等于在无确认情况下把「监测」固化为默认行为，与纪律相悖。
5. **询问成本极低、收益确定**。每次会话初始化多一次一问一答，摩擦可忽略；换来的是「启动前必获授权」，可逆、可审计、符合用户主权，风险收益比显著占优。
6. **避免对用户假设默认**。各 Agent 对「默认启用」的合理边界理解可能不同（间隔、范围、触发条件），以显式询问替代隐式假设，把定义权交还 Rainier。

### 四、风险与代价

1. **增加一次初始化交互**。每个新会话多一次询问，若 Rainier 每次都需选择，会产生轻微重复摩擦。
2. **存在遗漏监测的可能**。若 Rainier 选择不启用或忘记确认，辅助定时监测不生效，仅靠主机制（回复前必查）兜底，覆盖频率下降。
3. **跨会话重复确认**。询问结果会话级存储，跨会话需重新确认，可能造成重复成本；若 Rainier 期望持久化授权，则需另行约定。
4. **与其他参与者策略不一致**。若其他参与者倾向「默认启用」而我倾向「显式询问」，监测覆盖会出现差异。此为需 Rainier 统一拍板后写入规范的原因，非本方案自身缺陷。
5. **兜底充分、风险可控**。主机制始终生效，即便辅助监测关闭，协作的「回复前必查」检查仍能保证基本监测不缺失，故整体风险有限。

### 五、待确认问题

1. 「显式询问」是否限定在会话初始化阶段？是否允许 Rainier 在会话中途随时开启 / 关闭？
2. Rainier 对询问的选择是否需要持久化（跨会话记住上次选择），还是每次会话都重新确认？
3. 若 Rainier 选择启用，扫描间隔是否固定为 2 分钟，还是允许按会话自定义？
4. 三个参与者若方案不一致，是否由 Rainier 统一拍板、收敛为单一策略写入协作规范？
5. 「默认不启动」期间，是否需要在初始化输出中预留一个始终可见的监测状态提示，便于 Rainier 感知当前未启用，避免「以为在监测、其实没开」的误解？
