## 提案正文

### 一、对任务的理解

本次讨论要收敛的问题是：多 Agent 协作 Skill 中「两分钟辅助监测」（每两分钟扫描一次工作区/讨论文件夹）的**默认启用策略**，候选选项为「默认启用 / 默认关闭 / 显式询问后启用」，期望产出可写入协作规范的可执行方案。

我理解「默认启用 / 默认关闭 / 显式询问后启用」三者的本质区别在于**资源占用与可用性之间的权衡**：默认启用保证即使参与者走神也能及时感知新内容，但持续消耗 token/算力；默认关闭省资源但依赖参与者的主动性；显式询问把选择权交给人在每次会话开始时决定。

我的立场是：**默认关闭两分钟辅助监测，仅在需要时（由参与者或 Rainier）显式启用**。理由以 token/成本优先为主线，同时避免把「监测」误读为永久后台轮询。

### 二、提案内容

**核心方案：默认关闭 + 按需显式启用。**

具体分三层：

1. **规范默认态为「关闭」**
   - 协作规范中明确写出：两分钟辅助监测默认**不自动开启**。
   - 主机制是「每次向用户回复前检查讨论文件夹是否有新内容」（现有规范第六条 a），这一条必须保留并作为强制基线，因为它零轮询成本、仅在参与者主动行动时触发。

2. **显式启用条件（满足其一即启用）**
   - 会话开始前或讨论过程中，由 Rainier（决策者）明确要求「开启监测」；
   - 讨论处于**等待收敛、长时间无人发言**的关键阶段，某参与者主动提出「我来盯着文档，有新内容我回」；
   - 参与者自报当前会话资源充足（token 预算充裕），愿意承担持续轮询成本。

3. **启用的实现与边界约束**
   - 启用后即为**有界监测**，不是永久轮询：按现有规范第六条 b 的停止条件执行（用户明确停止 / 讨论文档已转 word 后自行停止）。
   - 明确告知：定时扫描依赖会话级机制（cron），会话退出即失效、约 7 天自动过期，跨会话需用户重新激活——因此定时扫描永远只是辅助，不能当作可靠的持久通道。
   - 启用时应一次性向 Rainier 声明「我将在本会话内每隔 2 分钟扫描一次讨论文件夹」，避免把默认行为误读为永久轮询。

**一句话落地方案**：规范正文写「两分钟辅助监测默认关闭；需启用时由参与者显式声明并遵守有界停止条件」，把「每次回复前检查」作为唯一无条件强制项。

### 三、主要依据

1. **成本与 token 优先**：两分钟一次定时扫描是持续的后台开销，讨论若长时间无人发言，轮询产生的 token/算力浪费与收益不成比例。默认关闭最省资源，符合「优先使用简洁方案，拒绝过度设计」的原则。
2. **避免被误读为永久轮询**：会话级 cron 有约 7 天自动过期、会话退出即失效的特性。若规范默认「启用」，参与者可能误以为监测是可靠的持久通道，从而放松「每次回复前检查」这条主机制——反而更危险。
3. **主机制已足够兜底**：现有规范第六条 a「每一次向用户回复前，先检查讨论文件夹是否有新内容」是零成本且可靠的主动触发点。只要这条保留，默认关闭辅助监测不会造成漏读。
4. **把选择权留在需要时**：辅助监测的本质是「从被动发现变为主动盯梢」，只有进入等待/收敛阶段才真正有用。此时由参与者显式声明启用，语义清晰、双方知情，符合协作规范「只有用户明确确认才算决策」的纪律。

### 四、风险与代价

1. **漏读风险**：默认关闭后，若参与者不遵守「每次回复前检查」主机制，可能遗漏他案更新，导致回应滞后。代价：需要更强的纪律约束，或在规范中把主机制标记为「强制性」。
2. **收敛速度下降**：在等待收敛的静默期，无人主动盯梢时，讨论可能停滞更久才被注意到。代价：可用「显式启用」覆盖此场景，但依赖有人记得启用。
3. **「关闭」可能被误解为「禁止」**：若措辞不当，参与者可能完全放弃扫描。缓解：措辞明确为「默认关闭，允许随时显式启用」，而非「不建议使用」。

### 五、待确认问题

1. 若某参与方要求默认启用，其 token/成本预算由谁承担、有无上限？（需 Rainier 或该参与方回应）
2. 「每次回复前检查」是否应升级为规范中的**无条件强制项**（即违反视为违规）？这决定默认关闭方案的风险敞口有多大。
3. 是否需要约定「显式启用」的固定措辞或状态位（例如在讨论文档头部标注「监测中：claude-b」），以便其他参与方和被占用方知悉？
4. 收敛结论应由 Rainier 拍板：默认关闭方案是否被接受，还是倾向「显式询问后启用」（会话开始人点一次头）？
